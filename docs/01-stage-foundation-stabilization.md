# Этап 1 — Стабилизация фундамента (обязателен перед продом)

Цель этапа: привести проект в единое рабочее состояние (структура, импорты, модель данных, базовая безопасность), чтобы дальнейшие фичи добавлялись без “расползания” кода.

## Результат этапа (Definition of Done)

- Одна корневая структура App Router (**только `app/`**)
- Один конфиг Next (`next.config.*`) и предсказуемая сборка
- Алиасы TypeScript соответствуют реальной структуре (`@/*` указывает в одно место)
- Prisma схема, миграции, API и UI используют **одну** модель Trade (без несовпадающих полей)
- NextAuth работает: login → сессия/JWT → защита роутов и API
- Все запросы к данным изолированы по `userId`
- Репозиторий чистый: `.next` и окружение не попадают в git status (проверка ignore)

## Работы

### 1) Выбрать единый корень маршрутов

Рекомендуемое решение:

- Перенести функциональность из `app/` в `src/app/` (или наоборот), затем удалить дубль.

Критерии:

- В проекте нет двух вариантов одной и той же страницы (`/dashboard`, `/login`, `/api/trades` и т.д.).

### 2) Нормализовать импорты и `paths`

Вариант A (рекомендуется): код живет в `src/*`.

- `tsconfig.json`:
  - `paths: { "@/*": ["./src/*"] }`
- Переместить `lib/*` и `components/*` в `src/lib/*` и `src/components/*`
- Обновить все импорты на `@/lib/...`, `@/components/...`

### 3) Убрать конфликтующие Next config

- Оставить один из: `next.config.mjs` или `next.config.ts`
- Удалить второй

### 4) Привести API “сделок” к Prisma-схеме (или схему к API)

Нужно выбрать модель “истины”.

Рекомендуемая (соответствует твоему ТЗ про несколько входов/выходов):

- `Trade` (трейд-группа): `symbol`, `marketType`, `direction`, `status`, `strategy`, эмоции, заметки, `fee`, `funding`, `createdAt`, `closedAt`
- `Entry[]`, `Exit[]` как отдельные операции (частичные входы/выходы)

Тогда API должен уметь:

- создать `Trade` в статусе `OPEN` + первый `Entry` (по нажатию “ввод сделки”)
- добавить `Entry` в существующий Trade (докупка/усреднение)
- добавить `Exit` (частичный выход)
- закрыть Trade автоматически, когда суммарный `exitVolume >= entryVolume` (или явная кнопка “закрыть”)

### 5) Настроить single-user авторизацию “по-взрослому”

Требования:

- без публичной регистрации
- один владелец (admin user), создается:
  - через seed (`prisma/seed.ts`) или
  - через hidden endpoint (только при пустой БД) + секретный ключ

Проверки:

- middleware защищает страницы и API, которые работают с данными
- API handlers получают `userId` из сессии и фильтруют/пишут данные только для владельца

### 6) Исправить типизацию/компиляцию

- Починить `src/lib/risk-manager.ts` (тип `Exit`)
- Удалить/переписать устаревшие `lib/calc.ts` и старые расчеты, если они конфликтуют с новой моделью

### 7) Восстановить минимальную документацию для запуска

Заменить `README.md` на проектный:

- как запустить
- `DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`
- команды Prisma (`migrate`, `seed`)

## Риски и типовые ошибки

- “Половинчатый перенос” (`app/`+`src/app/`) ломает маршруты и middleware непредсказуемо
- Несогласованная модель данных делает аналитику невозможной или неверной
- Без `userId`-изоляции single-user приложение превращается в публичный API
