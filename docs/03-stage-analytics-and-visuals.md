### PnL % и % доходности (знаменатель)

**Правило (согласовано):** знаменатель — **капитал на начало периода** (в том же скоупе счёта / журнала, что и выборка аналитики).

- Пусть `T_start` — левая граница выбранного периода **`[from, to]`** (момент времени в **UTC**, полученный из даты/времени в **часовом поясе приложения** после фазы **3.0**).
- **Капитал на начало периода** (`capitalAtPeriodStartUsdt`) = `capitalUsdtBeforeExclusive(T_start, …)` — закрытый PnL и **net cashflow** до `T_start` в скоупе журнала (`equity-timeline.ts`). Без cashflow — fallback `JOURNAL_INITIAL_DEPOSIT_USDT`.
- **Стартовый депозит** (`journalDepositUsdt`) = суммарный net cashflow в скоупе (карточка на `/analytics`; не путать с капиталом на `T_start`, если депозит внутри периода).
- **PnL % за период** = `totalPnl / roiDenom × 100%`, где `roiDenom` = капитал на `T_start`, а если он ≤ 0 — **`journalDepositUsdt`** (депозит внутри периода не даёт нулевой %).
- **Worst** — худшая **убыточная** сделка (только `pnl < 0`); **Best** — лучшая прибыльная. **Макс. ROI к депозиту** — max(`pnl / journalDeposit × 100%`) по сделкам периода.

## Источник данных и производительность

Рекомендуется считать агрегаты на сервере:

- API эндпоинт(ы) аналитики, принимающие фильтры + **timeZone** (или только серверное чтение сохранённого TZ пользователя)
- Prisma запросы с выборками `entries/exits` только в нужном диапазоне
- Архитектура: **route → service → repository**; **все финансовые агрегаты** — в одном модуле (например `analytics-metrics` / серверный слой), переиспользование **`calculateTradePnL`** для CLOSED; UI не считает PnL

Оптимизация:

- отдельные lightweight endpoints при необходимости (большие периоды)
- лимиты на диапазон дат при необходимости (анти-абьюз)

## Метрики (как минимум)

- **PnL**: сумма PnL по закрытым Trade в периоде (fee/funding учтены в движке)
- **PnL %**: знаменатель — **капитал на начало периода** (см. § выше)
- **Winrate**: count(pnl>0)/count(closed)
- **Avg win / Avg loss**
- **Risk/Reward**:
  - минимально: avgWin/abs(avgLoss)
  - после этапа 4: уточнение от риск-менеджмента

## Расширенные метрики (в этап 3)

> Источник: консолидация черновика из папки «Новые для анализа».

- **Sharpe Ratio** — (средняя доходность − безрисковая ставка) / стандартное отклонение доходности
- **Maximum Drawdown** — максимальная просадка от пика equity
- **Expectancy** — (средний выигрыш × winrate) − (средний проигрыш × loss rate)
- **Recovery Factor** — чистая прибыль / максимальная просадка
- **Average Holding Time** — среднее время от открытия до закрытия трейда

### Max PnL / ROI по периодам

- За день / месяц / год / всё время
- Отдельно: максимум на **одну сделку**
- Отдельно: ROI **относительно открытой позиции** (не от депозита), где применимо

### Winrate — детализация

- Количество сделок всего
- Количество прибыльных / убыточных
- Winrate = прибыльные / всего × 100%

## Тест-план

- Сравнить суммарный PnL из журнала (закрытые в том же периоде и скоупе счёта) и из аналитики — **должны совпадать**
- **PnL %:** руками проверить знаменатель: `JOURNAL_INITIAL_DEPOSIT_USDT` + Σ PnL закрытых с `closedAt < T_start` в том же скоупе; затем PnL периода / этот капитал
- Проверить группировки по дням/неделям/месяцам и **weekday/hour** в выбранном TZ
- Проверить фильтры по стратегии/символу и **journalAllAccounts**
- Проверить смену TZ в настройках и пересчёт границ дня / бакетов
- Экспорт CSV: колонки и числа согласованы с экраном
- Визуальная сверка со **всеми** PNG в `docs/`
