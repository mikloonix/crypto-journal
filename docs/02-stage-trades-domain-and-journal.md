# Этап 2 — Домен “Сделки/Трейды” + Журнал (core value)

Цель этапа: реализовать правильную доменную модель (spot/futures, открытие→закрытие, группировка в трейды) и удобный журнал сделок (таблица + карточки) с фильтрами по периоду.

## Definition of Done

- Пользователь создаёт **открытую** сделку (Trade) по нажатию “ввод сделки”
- Поддержаны **несколько входов/выходов** по одной монете в рамках одного Trade
- Закрытие Trade фиксирует `closedAt` (по кнопке подтверждения/условиям объёма)
- В UI при открытии вводятся: стратегия и эмоции входа
- В UI при закрытии вводятся: цена, объём выхода, эмоции выхода, комиссия, фандинг
- Журнал умеет группировать:
  - по дням/неделям/месяцам/кастомному периоду
- Есть быстрые фильтры: монета, стратегия, статус (OPEN/CLOSED), рынок (SPOT/FUTURE)
- Все CRUD операции защищены и работают только с `userId`

## Уже сделано (MVP в коде)

- Одна строка = один `Trade` (трейд-группа)
- Повторный вход по той же монете/направлению/рынку добавляет `Entry` в существующий OPEN-трейд
- Частичное закрытие создаёт `Exit`, показывает реализованный PnL и остаток объёма
- “Детали” раскрывают список `Entry/Exit` по трейду
- **`GET /api/trades`** с фильтрами query: `status` (OPEN/CLOSED), `symbol`, `strategy`, `marketType` (SPOT/FUTURE), период `from`/`to` (ISO), `dateBasis` (`createdAt` | `closedAt` | **`exitAt`** — трейды с хотя бы одним выходом в периоде; для списка «сделок» на `/trades/closed`). При любых фильтрах **`summary` / equity** считаются **только по возвращённому списку**; без query — по всем активным трейдам пользователя.
- **Журнал `/trades/closed`:** быстрые фильтры (период: сегодня / неделя / месяц / свой диапазон / всё), символ, стратегия, рынок; группировка строк по дням / неделям / месяцам (по дате закрытия); в таблице — рынок, агрегаты комиссии и фандинга по трейду, длительность (`journal.durationMs`); на узких экранах — **карточки** с теми же метриками и раскрытием входов/выходов.
- **Дашборд:** в таблице открытых добавлена колонка «Рынок».

## Данные (целевая модель — вариант A, `roadmap-full-v2.md`)

- **`Account`**: торгуемый счёт/субсчёт (биржа, режим маржи, валюта учёта). Каждый `Trade` привязан к `accountId`.
- **Trade**:
  - `userId`, `accountId`, `symbol`, `marketType`, `direction`, `status`
  - `strategy`, `emotionEntry`, `emotionExit`, `notes`
  - `fee`, `funding` — **агрегаты**, пересчитываются из сумм по `Exit` при каждом изменении
  - `createdAt`, `closedAt`
- **Entry**:
  - `timestamp` (сервер, по подтверждению)
  - `price`, **`margin`** (маржа в USDT), `leverage`
  - `stopLossPrice` (для FUTURE — обязателен в API/валидации)
  - `reason` / setup (опционально)
- **Exit**:
  - `timestamp` (сервер, по подтверждению)
  - `price`, **`margin`** (маржа, закрываемая этим выходом)
  - **`fee`**, **`funding`** — хранятся на уровне выхода; на `Trade` — только сумма

**Маржа vs объём контракта:** в UI везде «маржа»; объём контракта = `margin × leverage / price` (см. формулы в `roadmap-full-v2.md`).

**Времена:** UTC в БД, отображение в локали браузера.

## API контракты (примерный набор)

- `POST /api/trades` — создать Trade + первый Entry
- `POST /api/trades/:id/entries` — добавить Entry
- `POST /api/trades/:id/exits` — добавить Exit
- `POST /api/trades/:id/close` — закрыть Trade (фиксирует `closedAt`, `status`)
- `GET /api/trades` — список с фильтрами (период/статус/символ/стратегия)
- `DELETE /api/trades/:id` — удалить Trade целиком

## UI/UX (журнал)

- **Таблица** (desktop):
  - символ, направление, рынок, статус
  - средняя цена входа, средняя цена выхода
  - размер позиции/объем
  - PnL $ и %, комиссии, фандинг
  - длительность
- **Карточки** (mobile):
  - компактные данные + действия (добавить выход/вход, закрыть)
- **Быстрое создание**:
  - тикер выбирается из списка (см. этап 5/интеграции — биржевые пары)
  - время входа — автозаполнение (серверное время), но показывать в UI
  - валидаторы (zod) и обработка ошибок

## Расчеты

Нужно централизовать расчеты (один модуль/один источник):

- PnL на основе операций `Entry/Exit`, с учетом direction (LONG/SHORT)
- комиссии и funding
- ROI % относительно используемого депозита (определить правило: от `RiskSettings.accountBalance` или фиксированного initial balance)

## Тест-план (минимум)

- Создание Trade + Entry
- Добавление частичного выхода и проверка пересчета PnL
- Закрытие Trade и появление в “Closed”
- Фильтрация по датам и символу

## Риски

- Если не решить модель комиссий/фандинга сейчас, аналитика позже будет “кривой”
- Времена событий: лучше ставить на сервере, иначе будут расхождения между устройствами
