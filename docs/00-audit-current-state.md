# Crypto Trading Journal — аудит текущего состояния

Дата: 2026-05-02

## Контекст и целевое видение

Проект позиционируется как single-user веб‑приложение “Дневник трейдера” с доступом через интернет, облачным хранением, авторизацией, журналом сделок (особенно фьючерсы), аналитикой, риск‑менеджментом и импортом/экспортом.

## Текущий стек (по `package.json`)

- **Frontend**: Next.js (`next@^16.2.4`), React 18, Tailwind CSS, Radix UI, Recharts
- **Auth**: `next-auth@^4.24.5` + `@auth/prisma-adapter`
- **DB/ORM**: PostgreSQL + Prisma (`prisma@5.8.0`, `@prisma/client@5.8.0`)
- **Доп.**: `@supabase/supabase-js` присутствует, но Supabase-конфигурации в репозитории не найдено

## Критические проблемы (блокируют прод и часто ломают dev)

### 1) Дублирующая структура роутов: `app/` и `src/app/`

В репозитории одновременно существуют:

- `app/` (включая `app/api/trades/*`, `app/dashboard/page.tsx`, `app/page.tsx`)
- `src/app/` (включая `src/app/login/page.tsx`, `src/app/dashboard/page.tsx`, `src/app/api/auth/[...nextauth]/route.ts`)

Это почти гарантированный источник ошибок:

- разные страницы/роуты с одинаковыми путями могут “конкурировать”
- импорты/алиасы (`@/*`) могут указывать не туда
- middleware в `src/middleware.ts` может защищать одни маршруты, а UI использовать другие

**Решение**: выбрать единый App Router-root (рекомендуется `src/app/`) и удалить/перенести второй.

### 2) Несоответствие Prisma-схемы и API сделок

`prisma/schema.prisma` описывает торговую модель как:

- `Trade`: `symbol`, `marketType`, `direction`, `status`, `entries[]`, `exits[]`, `fee`, `funding`, `createdAt`, `closedAt`

Но `app/api/trades/*` работает с полями, которых в схеме нет:

- `ticker`, `entryPrice`, `entryTime`, `exitPrice`, `exitTime`, `volume`, `leverage`

Это означает одно из двух:

- текущие API **неработоспособны** с текущей схемой, или
- схема/код были частично переписаны и проект находится в “смешанном” состоянии

**Решение**: определить “источник правды” по модели сделки и привести UI+API+Prisma к одному контракту.

### 3) Ошибки импортов и алиасов (ломают сборку/типизацию)

В `tsconfig.json`:

- `@/*` → `./*` (корень репозитория)

При этом:

- Auth роут использует `import { authOptions } from "@/lib/auth"`, но **`lib/auth.ts` в корне нет** (есть `src/lib/auth.ts`)
- `src/lib/auth.ts` импортирует `prisma` из `@/lib/prisma`, но **`lib/prisma.ts` не найден** (есть `lib/db.ts`)

**Решение**: стандартизировать расположение `lib/` (например, `src/lib/*` + `paths: { "@/*": ["./src/*"] }`) и обновить импорты.

### 4) Защита API и мульти-tenant безопасность

Цель — single-user, но в коде уже есть `User` в Prisma. Это хорошо для будущего масштабирования, но сейчас:

- `app/api/trades/*` не проверяет пользователя и не фильтрует по `userId`
- middleware матчится на `/api/trades/*`, но только если реально используется тот root роутов, который middleware видит

Риск: утечки данных и возможность читать/удалять сделки без авторизации, если защита не применяется.

**Решение**: в каждом handler получать текущего пользователя из сессии/JWT и выполнять запросы только с `where: { userId: session.user.id }`.

### 5) Несогласованность в UI: две разные “Dashboard”

- `src/app/dashboard/page.tsx` — пытается использовать `useSession()` и редиректить на `/login`
- `app/dashboard/page.tsx` — простая таблица + расчёты и дергает `/api/trades` без учета пользователя

**Решение**: оставить одну версию и довести её до целевой модели (Trades→Trade groups, открытые/закрытые, аналитика).

### 6) TypeScript/логика: риск-менеджмент не компилируется

В `src/lib/risk-manager.ts` используется тип `Exit` без импорта/определения:

- `calculateTradePnL(trade: Trade & { entries: Entry[]; exits: Exit[] })`

**Решение**: импортировать `Exit` из `@prisma/client` или исправить тип.

### 7) Конфиги Next: одновременно `next.config.mjs` и `next.config.ts`

Два конфига обычно приводит к путанице, какой реально используется. Один из них пустой.

**Решение**: оставить один (`next.config.mjs` или `next.config.ts`) и удалить второй.

### 8) README не отражает проект

`README.md` — дефолтный create-next-app, отсутствуют:

- переменные окружения
- схема БД/миграции
- команда инициализации single-user
- деплой/бэкапы

**Решение**: заменить README на проектный.

## Функциональные пробелы относительно ТЗ

- **Сделки как “трейды” с несколькими входами/выходами**: частично отражено в Prisma (`Entry[]/Exit[]`), но UI/API работает как “1 вход — 1 выход”.
- **Поля эмоций/стратегий/причин**: в Prisma частично есть, но UI/API не покрывает.
- **Импорт/экспорт xlsx**: отсутствует.
- **Интеграция BingX**: отсутствует.
- **Риск‑правила и подсветка нарушений**: есть модель `RiskSettings` и черновик вычислений, но нет API/UI слоя.
- **Аналитика/графики**: есть базовый Equity Chart, но не по реальной модели, и не покрывает метрики.

## Итог

Проект содержит перспективные заготовки (Prisma-модель с `Entry/Exit`, NextAuth, middleware, Tailwind/Radix, Recharts), но сейчас находится в несогласованном состоянии по структуре и данным. До продакшна нужна “стабилизация фундамента”: единая структура роутов, единый контракт сделки, корректный auth+изоляция данных, затем постепенное наращивание функционала по этапам.
