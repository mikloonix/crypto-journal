# Этап 5 — Экспорт/импорт (xlsx) + интеграция BingX

Цель этапа: сделать переносимость данных и автоматизацию ввода — экспорт в Excel, импорт из Excel и импорт сделок с BingX (с перспективой авто-синхронизации).

## Definition of Done

- Экспорт всех сделок/трейдов в `.xlsx`
- Импорт из `.xlsx` с валидацией и отчетом об ошибках
- Импорт сделок с BingX:
  - ручной запуск “Sync”
  - корректное сопоставление в модель Trade/Entry/Exit
- Безопасное хранение API ключей (если используется API)

## Экспорт `.xlsx`

Минимально:

- лист `Trades` (трейды): id, symbol, marketType, direction, createdAt, closedAt, strategy, emotions, notes, fee, funding, pnl, roi
- лист `Entries` и `Exits`: привязка по `tradeId`, timestamp, price, volume, leverage

Требования:

- единая таймзона (желательно UTC в файле + отображение локально)
- корректные типы ячеек (даты как date, числа как number)

## Импорт `.xlsx`

Подход:

- загрузка файла → предварительный парсинг → “preview” (что будет создано/обновлено)
- строгая валидация (zod)
- транзакция в БД (или батчи), чтобы не было “полу-импортов”

Идентификация:

- либо импорт всегда “создает новое”
- либо умеет upsert по уникальному ключу (trade external id)

## BingX интеграция (эскиз)

Нужно выбрать способ:

- **API** (ключ/секрет): предпочтительно для автоматизации
- **CSV/XLSX выгрузка** с биржи: проще, но менее автоматично

### Хранение ключей

Если используем API:

- хранить ключи **в БД** в зашифрованном виде (KMS/PGP/crypto), либо использовать Supabase Vault/аналог
- не хранить секреты в localStorage
- ограничить ключи правами “read-only”

### Маппинг сделок

Биржа может отдавать “fills” (исполнения), которые лучше маппить на:

- `Entry/Exit` как операции
- группировку в `Trade` по:
  - symbol
  - direction
  - близость по времени
  - `positionId`/`orderId` если доступно

## UI

- Экран “Import/Export”
- Кнопки:
  - Export all
  - Import xlsx
  - Sync BingX
- Логи синхронизации (последний sync, сколько записей добавлено/пропущено)

## Тест-план

- Экспорт → затем импорт в пустую БД → совпадение метрик и количества записей
- Импорт с намеренными ошибками → корректный отчет и отсутствие частичных записей
- BingX sync повторно → идемпотентность (не плодим дубликаты)
