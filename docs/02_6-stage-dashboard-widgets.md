## Календарный день и часовой пояс

- **Текущая реализация:** граница дня — **IANA из настроек** (`displayTimeZone`), иначе полночь браузера; клиент передаёт `dayStart` / `dayEndExclusive` (ISO). Сервер фильтрует **время выходов** в `[start, endExclusive)`.
- **Этап 3.0:** единый **IANA timezone** из **настроек приложения** (см. [`03-stage-analytics-and-visuals.md`](./03-stage-analytics-and-visuals.md), фаза 3.0) используется для календарного дня и аналитики; для **дневных метрик дашборда** границы дня после 3.0 считаются в этом TZ (с fallback на браузер, пока настройка не задана).
- Хранение в БД по-прежнему **UTC** (правило проекта).

## Счёт и журнал

- Тот же контракт, что и журнал на дашборде: **текущий активный счёт / все счета** (`journalAllAccounts`, `accountId` в запросе) — как в этапе **2.5**.

## 1. PNL / ROI за день (MVP)

### Расчёт

- **PNL за день (USDT)** = сумма `pnlRoiForExitLeg` по **всем выходам** с `timestamp` в выбранный календарный день (частичные выходы по **OPEN** тоже учитываются). Счётчик «Сделок за день (выходов)» = число таких выходов, не число полностью закрытых трейдов.
- **ROI за день** = `pnlUsdt / balanceAtDayStartUsdt × 100%` (см. `dashboard-service.getDayStats`, `equity-timeline.capitalUsdtBeforeExclusive`).

### Отображение

- Зелёный / красный для PnL за день.
- Блок сравнения с целью — **после 4.5**.

## 2. Блок «Усреднение»

### Анализ позиции

Для каждой **OPEN** позиции (в скоупе журнала):

- Безопасный диапазон = средняя цена входа × (1 ± safeZonePercent)  
- safeZonePercent = (риск% / 2) / плечо (упрощённо, как в исходной спецификации; риск% — из `RiskSettings`, плечо — из данных позиции)
- **Сходила на X%** — для LONG: откат от **max** цены после входа к текущей (нужен **high** за период **или** упрощение MVP: только текущая vs entry — зафиксировать в реализации минимальный вариант до котировок); для SHORT — симметрично от **min**.
- **Динамика за час** = (текущая цена − цена час назад) / цена час назад — **в MVP архитектурно под провайдера котировок**; до него: показ «нет данных» и/или опциональный ручной fallback.
- **Можно добавить** (оценка): текущий риск позиции, оставшийся дневной лимит (`riskPerDay` и использованное за день — по правилам этапа 4 / упрощение MVP из доступных полей), **дистанция до стопа** из **ручной цены стопа** на дашборде: безопасная маржа ∝ доступный риск / расстояние до стопа (формула в модуле расчётов, единая точка).

Дисклеймер в UI: расчёт **информационный**, не инвестиционная рекомендация.

### Источник цены

- **Целевое поведение:** переключатель **авто (биржа)** / **вручную**; авто реализуется **после** интеграции котировок.
- **MVP:** вручную для текущей цены; заготовки API/DTO под **QuoteProvider** (например `source: "manual" | "exchange"`, поля `priceNow`, `price1hAgo` nullable).

## Архитектура (реализация)

- Новый HTTP API (например `GET /api/dashboard/day-stats`, `GET /api/dashboard/averaging` или один агрегированный маршрут) с `userId`, фильтром счёта, параметром **локальной даты** и при необходимости **IANA timezone** (или смещение в минутах от клиента для расчёта границ дня — предпочтительно **IANA** для DST).
- Сервис собирает закрытые за интервал + открытые + `RiskSettings`, вызывает **модуль метрик дашборда** (без логики в route).
- UI дашборда: только запросы и отображение; ручные поля стопа/цены — state формы, передаются в запрос усреднения при пересчёте (POST с телом вводных — по выбору GET/POST для длины URL).
