# Этап 6 — Продакшн-готовность (деплой, надежность, наблюдаемость)

Цель этапа: подготовить приложение к реальному использованию “через интернет” — деплой, домен, HTTPS, бэкапы, миграции, мониторинг и политика данных.

## Definition of Done

- Есть выбранная платформа деплоя (быстро/дешево):
  - Vercel + managed Postgres (Neon/Supabase/Railway) или
  - Railway (app + Postgres)
- Настроены переменные окружения и секреты
- Миграции выполняются безопасно (CI/CD или manual runbook)
- Бэкапы БД включены и проверены (restore test)
- Есть базовая наблюдаемость:
  - логирование ошибок
  - health-check
  - (опционально) Sentry
- Документы по эксплуатации:
  - как обновлять
  - как восстановить данные
  - как ротировать ключи/секреты

## Безопасность

- `NEXTAUTH_SECRET` задан и не меняется без необходимости
- `NEXTAUTH_URL` корректный (production domain)
- Cookies secure + sameSite, HTTPS
- Ограничить rate-limit на login и API (минимальная защита от брутфорса)
- Заголовки безопасности (CSP на разумном уровне, X-Frame-Options и т.д.)

## Производительность

- Пагинация и индексирование (Prisma индексы по `userId`, `status`, `createdAt/closedAt`)
- Вынос тяжелых вычислений аналитики на сервер
- Кэширование справочников (список пар, стратегии, т.п.)

## Данные и политика

- Экспорт/удаление данных пользователя (single-user, но все равно важно)
- Политика хранения скриншотов (если добавится):
  - S3-совместимое хранилище, signed URLs

## CI/CD (минимум)

- `npm run lint`
- `npm run build`
- (опционально) `prisma validate`
- Автодеплой на main

## Runbook (коротко)

- **Deploy**: шаги + откат
- **DB migrate**: когда и как
- **Backup/restore**: частота, где лежит, как проверить
